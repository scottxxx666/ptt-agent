# Weverse (`--source weverse`)

Same pipeline, other source: `weverse.fetch_lives` → `translator` → `pipeline.run_daily` → `formatter.build_weverse_*` → `PttPoster`. **One post per Taipei day**, titled `[影音] YYMMDD weverse live` (no member). The body has one block per live: translation in yellow, member name in cyan, blank line, live URL.

`run_daily` looks up that day's post (`PttPoster.find_post_aid`: this account's last 10 posts whose title contains `YYMMDD weverse live`, so a hand-made post counts too). If it exists, each new live of that day is added as an arrow comment (`PttPoster.comment`; PTT has no edit API in PyPtt; comments have no colour and PyPtt splits them at the board's line width, so the URL may wrap). If not, the lives seen in this run become the post. There is no seen-by-hand guard. Real-board behaviour of the lookup and the comment is unverified; try it on `Test` first.
- No browser. `weverse.fetch_lives` calls Weverse's web API directly (`urllib`): `communityIdUrlPathByUrlPathArtistCode` → `liveTab` (running, `onAirLivePosts`) and `liveTabPosts` (ended). Each URL carries `wmsgpad` (ms timestamp) and `wmd` = base64 HMAC-SHA1 of the first 255 chars of path+query plus the timestamp. The key, appId and account-API secret are public web-client constants copied from yt-dlp's `extractor/weverse.py`; if requests start failing with the token still valid, diff against that file first.
- Auth is the `we2_refresh_token` cookie in `.weverse-token.json` (`WEVERSE_TOKEN_PATH`; gitignored, 0600; VM: `/opt/ptt-agent/weverse-token.json`). The refresh token rotates on every refresh and the job writes the new one back, so each machine needs its own token file; never share one between the Mac and the VM. The access token is refreshed when it is within 5 min of expiry or on a 401. A rejected refresh token raises `WeverseError`; reseed it (README: Weverse token).
- `parse_lives` input is `{"onAirLivePosts": ..., "liveTabPosts": ...}`. A running live has the same post ID/URL as its replay, so it is posted once, while on air (state is keyed by ID).
- Member comes from `author.artistOfficialProfile.officialName` (stable), never from the nickname. `formatter.MEMBER_ZH` maps it to the name shown in the body (given name; Japanese members stay in Latin: SAKURA, KAZUHA); an unknown name is skipped, logged and notified until added. The group account (`profileType` GROUP) gets no name.
- State defaults to `state.weverse.dev.json`; the live job only runs on the VM (`deploy/ptt-agent-weverse.service`, `STATE_PATH=/opt/ptt-agent/state.weverse.json`). A missing state file means first run: existing lives are marked seen, nothing is posted, so a live that starts before that first run is never posted.
